# Hotel-Booking-Android — «Гостиница»

Курсовая работа Арзимуротова А.М., ПИН-123. Android/Kotlin + Ktor + PostgreSQL.
Исходники: [GitHub](https://github.com/AbdullaArzimurotov/Hotel-Booking-Android).

## Текущий результат — этапы 1–9, версия 0.9.0

**Самостоятельная учебная Android-система.** Готовый APK работает с первого запуска
без интернета, ноутбука, USB, Ktor, PostgreSQL, Google-ключа и внешнего аккаунта.
Основная база — Room/SQLite: 3 страны, 6 городов, 36 демонстрационных гостиниц,
108 типов и 432 номера, 30 мест. Поиск, регистрация, профиль, услуги, брони,
демооплата, история, восстановление пароля и полный ADMIN-кабинет — локальные.
Встроены шесть небольших Mapsforge/OSM-карт центральных районов.

Каждый телефон — отдельная demo-база. Заказы не синхронизируются между устройствами,
реальные гостиницы не бронируются, деньги не списываются. Часы телефона задают время
резерва и отмены. Интернет меняет только возможность отправить письмо почтовым клиентом.

### Установка и вход

Готовые артефакты находятся локально в `output/apk` после финальной сборки.
Release-пакет `ru.arzimurotov.hotel.offline` устанавливается независимо от старого
debug `ru.arzimurotov.hotel`; старую установку/базу удалять не нужно.

| Роль | Начальный login | Начальный пароль |
|---|---|---|
| ADMIN | admin@hotel.demo | HotelAdmin!2026 |
| USER | client@hotel.demo | HotelClient!2026 |

Это публичные учебные аккаунты, не почтовые ящики. Можно зарегистрировать собственный
email. При первом входе сохраните индивидуальный код восстановления; скрытого
универсального сброса нет. Пароли хешируются Argon2id; код после применения меняется.

### Android Studio / Mac / Asus

Клонируйте **весь** репозиторий. Откройте `android` в Android Studio, выберите
встроенный JBR 25, API 36, конфигурацию `app` и нажмите Run. Запускать backend не нужно.
Первый Gradle Sync требует интернет; уже установленный APK — нет.
На Mac: `cd android` → `./gradlew :app:assembleDebug`.
На Windows: `cd android` → `.\gradlew.bat :app:assembleDebug`.
Локальные пути `local.properties`, `.local`, ключи подписи и базы не копируются через Git.

### Подтверждения и почта

Оплаченный demo-заказ получает красивое HTML-подтверждение. PAY_AT_HOTEL — документ
о неоплаченном заказе. Сохранение через системный диалог; отправка через установленный
Gmail/Mail.ru с подготовленными получателем, темой, текстом и HTML-вложением.
Пользователь сам нажимает «Отправить». APK не выполняет SMTP, не обещает доставку
и не отправляет письма автоматически. Старый PDF-модуль остаётся только на backend.

## Архив реализации этапов 3–6 — версия 0.6.0

Ниже описана **сохранённая историческая серверная реализация**, не режим работы APK 0.9.0.
Её ограничения и команды не относятся к текущему самостоятельному приложению.

Каталог действительно хранится в PostgreSQL: 3 страны (Узбекистан, Россия, Турция),
6 городов, 36 вымышленных гостиниц 3–5 звёзд, 108 типов и 432 физических номера,
30 городских мест. Никакие сведения не импортируются из Booking.com.
Фотографии — встроенные учебные иллюстрации, не снимки реальных гостиниц.

Работают русские экраны поиска, фильтры, карточки, галерея, избранное,
регистрация email/пароль, вход, редактирование имени/телефона и выход.
Для ADMIN есть серверная сводка только для чтения.
Каталог берётся только из REST API: без backend показываются ошибка и повтор.
Скрытого fallback на локальную фабрику нет; постоянный Room-кэш пока не реализован.

Поиск выполняется в PostgreSQL по датам, гостям, количеству свободных физических номеров,
тарифу на весь период, цене, категории, рейтингу, удобствам, расстоянию и названию.
Заказы с несколькими номерами и услугами записываются одной транзакцией. Встреча в аэропорту
сохраняет аэропорт/рейс/местное время/телефон. Сервер повторно проверяет наличие и цену.
ONLINE_DEMO резервирует номера на 15 минут; PAY_AT_HOTEL сразу подтверждает неоплаченный заказ.
Есть история, отмена по сохранённой политике, аннулирование демооплаты и нефискальный PDF
с возможностью сохранить через системный диалог Android и передать на печать.
**Деньги не списываются. Гостиницы/услуги вымышлены; реальная машина не вызывается.**
Карта, Room и полный CRUD администратора — этапы 7–8. Билеты/такси/автомобили — позднее.
Избранное не синхронизируется с аккаунтом; SavedStateHandle восстанавливает сеанс/Activity.

## Пройти гостиничный сценарий

1. «Поиск»: выберите страну, город, будущие даты и гостей. Нажмите «Найти гостиницу».
2. Откройте гостиницу; сервер выдаст типы номеров, подходящие на весь период.
3. «Выбрать и оформить»: выберите услуги. Для трансфера обязательны аэропорт, рейс,
   время формата `2026-11-01T12:00` и телефон. Время местное для города проживания.
4. Войдите/зарегистрируйтесь. После входа вернитесь к оформлению и подтвердите сумму.
5. ONLINE_DEMO: в «Брони» нажмите «Выполнить демооплату» до истечения резерва.
   PAY_AT_HOTEL: заказ сразу подтверждён, статус оплаты остаётся UNPAID.
6. После демооплаты «PDF-подтверждение» → «Сохранить PDF» / «Печать».
7. Отмена доступна для ожидающего резерва либо до сохранённого cancelUntil.
   Типовая политика: 24 часа до заезда 14:00 местного времени. Выезд 12:00.

Учебные room_blocks созданы на три дня начиная с даты первого запуска этапа 4 + 7 дней.
Это не клиентские брони. Повторный запуск не переносит их даты. Прочие гостиницы доступны;
затем на наличие влияют и ваши SQL-заказы.

## MacBook: запуск через Android Studio

1. В терминале корня проекта: `python3 scripts/dev.py server`.
   Команда запускает отдельную базу на 55432, применяет Flyway и seed, затем Ktor на 8080.
   Терминал оставьте открытым. Пароли/JWT-ключ создаются автоматически в игнорируемой `.local`.
2. Откройте **android** в Android Studio, дождитесь Sync. Выберите JBR 25, Wrapper 9.2.1.
   Не отделяйте android от shared/gradle/server/scripts всего репозитория.
3. Выберите конфигурацию **app** и нужное устройство, нажмите зелёную кнопку Run.
4. Эмулятор: в debug-приложении «Подключение → Эмулятор», адрес 10.0.2.2:8080.
   Xiaomi/USB: сначала `python3 scripts/dev.py usb`, затем «Подключение → Телефон USB».
   Это adb reverse и 127.0.0.1:8080; IP ноутбука не нужно открывать в сети.
   После повторного подключения USB команду usb выполните снова.
5. `python3 scripts/dev.py smoke` проверяет реальный HTTP/SQL.

Настройка подключения доступна из ошибки каталога, профиля и диагностики.
Смена backend очищает текущую авторизацию и RAM-каталог — аккаунты разных баз не смешиваются.
Ctrl+C останавливает Ktor; `python3 scripts/dev.py stop-db` останавливает свою базу без удаления данных.
Длинные пути на Mac поддерживаются: PostgreSQL использует только TCP, Unix socket отключён.

## Аккаунты и администратор

Регистрация: имя, email, пароль 10–128 символов, подтверждение, необязательный телефон.
Email нормализуется; регистрация создаёт только USER.
JWT живёт 30 минут; после истечения требуется повторный вход. Refresh, восстановление
пароля, SMS/email-подтверждение и Google login не реализованы.

Администратора создаёт только локальная команда `python3 scripts/dev.py create-admin`.
Она скрыто запрашивает пароль; общих стандартных учётных данных нет.
Может работать при запущенном сервере; существующий USER не повышается до ADMIN.
Сводка доступна после входа администратором, все права проверяет backend по текущей SQL-записи.

## Сборка и проверки

Из корня:
```sh
python3 -m unittest discover -s scripts -p "test_*.py"
python3 scripts/dev.py test-sql
python3 scripts/ui_tests.py --serial emulator-5554
```
test-sql создаёт отдельную БД hotel_coursework_test_<random>, сохраняет её для аудита;
основную БД никогда не очищает. UI-скрипт принимает только явно указанный emulator-NNNN,
устанавливает APK с -r и не удаляет его. **Не используйте connectedDebugAndroidTest
при подключённом личном телефоне:** Gradle может выбрать все устройства и удалить приложение.

Из android (JAVA_HOME — JBR Android Studio):
```sh
./gradlew --no-daemon :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
./gradlew --no-daemon :app:assembleRelease :app:dokkaGeneratePublicationHtml
```
Из server:
```sh
./gradlew --no-daemon test installDist dokkaGeneratePublicationHtml
```
Без переменных HOTEL_TEST_DB_* SQL-интеграционный тест пропускается, остальные backend-тесты выполняются.
Debug APK: android/app/build/outputs/apk/debug/app-debug.apk.
Release без публичного сервера использует заглушку https://hotel.invalid/ и не является готовым
публичным сервисом. HTTP разрешён только в debug для 10.0.2.2 и 127.0.0.1.
SDK 36 / minSDK 26; AGP 9 использует built-in Kotlin, kotlin.android добавлять не нужно.

## Безопасность и два ноутбука

Пароли — Argon2id (19 MiB, t=2, p=1), JWT — HMAC256 с приватным ключом;
Android хранит JWT AES-GCM/Keystore в noBackupFilesDir, не сохраняет пароль.
В production необходимы HTTPS, развёртывание, мониторинг и усиленная эксплуатационная защита.
Текущий backend доступен только на 127.0.0.1; пользовательские базы вне проекта не затрагиваются.

Перед работой: `git pull --ff-only origin main`. После: проверьте diff, русское сообщение
коммита и `git push origin main`. Не применяйте force push.
Git синхронизирует **код, а не SQL-базы/аккаунты**. На Asus первый server создаст свою базу
с тем же seed, но независимыми пользователями/секретами.
Не переносите .local, local.properties, .idea, SDK, signing keys и токены между ноутбуками.
Происхождение изображений: [ASSETS](docs/ASSETS.md).
Исторические протоколы этапов 1–3 сохраняются, актуальное состояние — этапы 3–6.
