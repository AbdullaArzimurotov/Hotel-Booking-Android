# Протокол проверки этапа 1

Дата: 01.10.2026. Проект: «Гостиница», версия 0.1.0.
Среда: MacBook Air M4, macOS, Android Studio 2026.1, встроенный JBR 25.0.3.

## Объем результата

Реализована и проверена платформа Android → Ktor REST API → PostgreSQL.
Это **не готовая система бронирования**: предметный каталог, авторизация, заказы,
услуги, демооплата и административные операции относятся к следующим этапам.
Первая миграция содержит только метаданные проекта и историю миграций.

Зафиксированные инструменты: Gradle Wrapper 9.2.1 с проверкой SHA-256,
AGP 9.0.1, встроенный Kotlin 2.2.10, KSP 2.3.12, Compose BOM 2025.08.01,
Hilt 2.59.2, Ktor 3.2.3, Exposed 0.61.0, Flyway 11.20.3, Dokka 2.2.0.
compileSdk/targetSdk 36; minSdk 26; целевой JVM-байткод 17.
Версии прямых зависимостей находятся в `gradle/libs.versions.toml`.

## Проверка настоящей базы и REST

Использована PostgreSQL **18.4** из Postgres.app. Проект получил собственный кластер
`.local/postgres`, базу `hotel_coursework`, порт 55432 и пользователя `hotel_app`.
Существующий кластер пользователя на порту 5432 не запускался и не изменялся.

Команда `python3 scripts/dev.py smoke` фактически получила:

```json
GET /health → HTTP 200
{"status":"ok","service":"hotel-coursework","version":"0.1.0"}

GET /api/v1/health → HTTP 200
{"status":"ok","database":"connected","service":"hotel-coursework","version":"0.1.0","stage":1}
```

Readiness выполняет `SELECT 1` через Exposed и JDBC, а не возвращает заранее заданный
успешный ответ. Flyway выполнил V1; SQL подтвердил `version=1`, `success=true`,
`project_name=Гостиница`, `schema_stage=1`. После перезапуска метаданные сохранились,
повторный запуск проверил миграцию и не создал дублирующих записей.

Дополнительный сценарий отказа: остановлен только проектный PostgreSQL. В этот момент
`/health` вернул HTTP 200, а `/api/v1/health` — HTTP 503 с `status=degraded` и
`database=unavailable`. После `start-db` readiness вновь вернул HTTP 200 без перезапуска
приложения сервера. Так проверено восстановление JDBC-пула.

Пароли автоматически сгенерированы; файл имеет права 600 и исключен из Git.
TCP и Unix-сокет требуют SCRAM-пароль. Отдельная проверка входа через Unix-сокет
без пароля завершилась отказом `no password supplied`. Прикладной пользователь не имеет
прав суперпользователя, создания баз или ролей. Сервер слушает только `127.0.0.1:8080`.

## Проверка Android

Создан отдельный AVD `HotelCoursework_API36`: Pixel 6, Android 16/API 36,
Google APIs, ARM64 (`arm64-v8a`), экран 1080×2400, плотность 420 dpi.
Эмулятор запущен один; существующий Pixel_8_Pro/API 37.1 не изменялся.
При запуске emulator 36.6.11 выделил 2560 МБ RAM.

APK установлен через adb; запуск `ru.arzimurotov.hotel/.MainActivity` завершился успешно.
Визуально проверены русский текст, карточка соединения, кнопка и сообщения. При работающем
backend экран показал «Система готова» и оба значения «Подключено». После остановки
backend показал «Нет соединения с системой» с инструкцией восстановления.
Убран недостаточный контраст системных значков на темном заголовке.
В crash-буфере после запуска приложения записей не обнаружено.

Скриншоты сохранены локально и не входят в Git:
`.local/screenshots/foundation-ready.png`, `.local/screenshots/foundation-offline.png`.
После instrumentation-тестирования APK установлен заново: тестовый runner удаляет
установленные им пакеты при завершении прогона.

Это предварительный прогон платформы на одном телефоне, **не выполнение требования о трех
виртуальных устройствах**. Финальная матрица API 30 / 35 / 36 (планшет) остается на этапе 9.
