# Протокол этапов 3–6 — версия 0.6.0

Дата: 02.10.2026. Проект «Гостиница», Арзимуротов А.М., ПИН-123.
Это практические этапы разработки, не номера глав пояснительной записки.

## Объём результата

- Этап 3: PostgreSQL-каталог, email/пароль, Argon2id, JWT 30 минут,
  шифрованный Keystore-сеанс, собственный профиль, роли и ADMIN read-only summary.
- Этап 4: серверная SQL-фильтрация/сортировка/пагинация, тариф на весь
  интервал и отдельная физическая комната, demo room_blocks без фиктивных броней.
- Этап 5: один заказ на 1–4 комнаты одного типа, услуги и аэропортный трансфер,
  повторная проверка цены/наличия под блокировками, снимки и идемпотентность.
- Этап 6: 15 минут ONLINE_DEMO, PAY_AT_HOTEL/UNPAID, кабинет/история/отмена,
  демоплатёж/аннулирование, обслуживание сроков и нефискальный PDFBox-документ.

Каталог: 3 страны, 6 городов, 36 гостиниц, 108 типов, 432 комнаты, 30 мест.
Миграции V1–V5 применяются без изменения V1 и удаления существующих данных.
Деньги не списываются; заказ не передаётся реальной гостинице или перевозчику.

SQL-набор повторно выполнен в отдельной `hotel_coursework_test_de69c0d76332` на локальном
PostgreSQL 18. Тестовая база сохранена; основная `hotel_coursework` не очищалась.
Без HOTEL_TEST_DB_* четыре SQL test cases пропускаются, поэтому обычный Windows
workflow не выдаётся за проверку PostgreSQL. Настоящий SQL проверен отдельно на Mac.

Backend-набор содержит крупные интеграционные сценарии с несколькими assertions,
а не отдельный JUnit-метод на каждое бизнес-правило:

1. Миграции с нуля и повторное открытие, повторный seed, сохранение ручной правки.
2. Повторный email, неверный пароль, испорченный/истёкший JWT, inactive и роли;
   USER не получает ADMIN, клиент не повышает роль через register/profile.
3. Фильтры, стоимость, страницы, буквальный поиск с SQL-подобным вводом,
   тариф/интервал и недопустимость суммирования разных комнат по частям поездки.
4. Конкурирующее выделение комнат, нехватка N комнат и отсутствие частичного заказа;
   соседние интервалы без общей ночи не конфликтуют.
5. Один ключ/один заказ, изменённое содержимое с прежним ключом — 409;
   повтор платежа не продлевает резерв и не создаёт второй платёж.
6. Услуги PER_NIGHT_ROOM/ONCE, обязательные данные трансфера, PRICE_CHANGED,
   сохранение старой стоимости/названия в snapshot после редактирования каталога.
7. Истёкший резерв освобождает доступность без ожидания фоновой задачи;
   обслуживание EXPIRED/COMPLETED и запрет поздней отмены.
8. Гонка pay/cancel, максимум один платёж, итоговая отмена и освобождение комнат;
   параллельные pay/cancel/maintenance после срока не создают оплату истёкшего резерва.
9. Чужой заказ/PDF недоступен; неизвестные реквизиты карты отвергаются.
10. Искусственный сбой PDF не отменяет PAID; повторная генерация успешна,
    кириллица/длинный текст/многостраничность проверяются PDFBox: 70 услуг,
    длинное имя с emoji, минимум три страницы и наличие последней услуги.

Android JVM дополнительно проверяет отмену устаревшего поиска и отсутствие выдуманного
результата при IOException, дубль submit и очистку персонального состояния при выходе,
включая поздний ответ неотменяемого fake-репозитория.

## Устройства и безопасная методика

AVD: HotelCoursework_API36, ARM64, Pixel 6, API 36, emulator-5554.
UI runner принимает только явно заданный emulator-NNNN, ставит APK через install -r,
не вызывает connectedDebugAndroidTest и не удаляет приложения с личного телефона.

Xiaomi 12 Pro: Android 16 / API 36, USB + adb reverse tcp:8080 tcp:8080.
Обновление только install -r: без uninstall/clear data. Для ручного smoke используется
учебный аккаунт; пароли/JWT остаются только в игнорируемой .local и не публикуются.

Проверенный SQL-заказ HC-BFED61BB-484B: Москва, «Резиденция света»,
10–12 октября 2026, стандарт, комната 102, два взрослых, трансфер SVO/SU100.
Проживание 31500 RUB + трансфер 4500 RUB = 36000 RUB.
Сразу после создания экран показал PENDING_PAYMENT и 14:59, после демооплаты —
CONFIRMED/PAID; PDF сохранён через системный DocumentsUI в Download.
Документ визуально проверен: русские реквизиты, сумма и нефискальное предупреждение.

Второй заказ HC-853809BC-BB68: Ташкент, 9–12 октября 2026, стандарт,
комната 104, PAY_AT_HOTEL, завтрак 90000 × 3 = 270000 UZS;
проживание 4725000 + завтрак = 4995000 UZS. Сразу CONFIRMED/UNPAID,
кнопки демооплаты и оплаченного PDF отсутствуют. Оба учебных заказа отменены
на телефоне и перенесены в историю; первый отображает REVERSED и сохраняет
историческую квитанцию. Редактирование имени, выход и повторный вход проверены:
SQL сохраняет профиль, приложение не подставляет чужие/фиктивные данные.
После перезапуска Ktor и обновления APK оба заказа/профиль сохранились;
история повторно загружена с API. Проверка нового заказа из восстановленной
вкладки «История» показала автоматический переход в «Активные».

На устройстве обнаружена и устранена ошибка PrintManager: русская локаль не должна
подменять Activity baseContext через createConfigurationContext. Используется
applyOverrideConfiguration, печать вызывается из LocalActivity; при отсутствии
Activity/службы показывается подсказка вместо падения. Дополнительный UI regression
проверяет этот безопасный отказ. Физического принтера в проверке нет: проверяется
системная подготовка/предпросмотр документа, а не печать на бумаге.
На Xiaomi после исправления открылся PrintSpooler: ISO A4, «Страница 1. Всего: 1».
После нового заказа кабинет автоматически открывает «Активные», а не восстановленную
старую «Историю». Этот случай выделен в отдельный Compose regression test.

## Повторить проверку

Из корня репозитория:

```sh
python3 scripts/dev.py server
python3 scripts/dev.py smoke
python3 scripts/dev.py test-sql
python3 scripts/dev.py usb
python3 scripts/ui_tests.py --serial emulator-5554
python3 -m unittest discover -s scripts -p "test_*.py"
```

Android Studio открывает android, конфигурация app → Run.
На Asus — [Windows инструкция](WINDOWS.md); база и аккаунты отдельные,
Git переносит исходники, а не данные локальной PostgreSQL.
