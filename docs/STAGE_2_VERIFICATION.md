# Протокол этапа 2 — интерфейс и навигация

Дата: 01.10.2026. Android-приложение 0.2.0 (versionCode 2).
Среда: MacBook Air M4, Android Studio JBR 25, Gradle 9.2.1, compile/target API 36.
Сервер остаётся версии 0.1.0: изменение UI не означает реализацию новых REST-операций.

## Выполненная работа

- Четыре основных раздела; отдельные маршруты результатов, гостиницы, галереи,
  расчёта, избранного, места и диагностики. Navigation Compose 2.9.3.
- Русский интерфейс, включая Material-календарь. Язык приложения не зависит от
  языка эмулятора. App Bundle не разделяется по языкам.
- Локальный `CatalogRepository`: 36 вымышленных гостиниц (по 6 в городе,
  по 2 категории 3/4/5 звёзд) и 30 вымышленных городских мест.
- Поиск по направлению и названию, даты, взрослые/дети/номера, звёзды, рейтинг,
  бюджет, удобства, тип номера; порядок по цене, рейтингу и удалённости от центра.
- Цена фильтра и сортировки относится к типу номера, подходящему по вместимости.
  Разные валюты не сравниваются численно: поиск ограничен выбранной страной.
- Галерея из трёх локальных иллюстраций, полный просмотр и избранное.
- Предварительный расчёт проживания и услуг; завтрак умножается на ночи и номера,
  трансфер считается один раз на заказ. Пример: стандарт в «Резиденции света» в
  Ташкенте на 3 ночи и один номер + трансфер = 5 175 000 сум.
- Честные состояния гостя и отсутствия заказов; без имитации аккаунта, успешной
  оплаты или брони. Ошибка каталога имеет повторную загрузку.
- `BrowseViewModel` + `SavedStateHandle`: восстановление формы, фильтров и избранного,
  сброс устаревших дат. Экранные состояния навигации восстанавливаются при recreation.
- Существующая реальная диагностика Ktor/PostgreSQL перенесена в профиль.
- На широком экране — NavigationRail и двухколоночный каталог; на телефоне — нижняя
  панель и одна колонка. Форма, карточки и диалоги допускают прокрутку.

## Конфигурации экранов и артефакты

Использован только проектный ARM64 AVD `HotelCoursework_API36`, Android 16/API 36:

- телефон: 1080 × 2400 px, 420 dpi;
- планшетное окно: временный `wm size 1600x2560`, `wm density 240` (ширина 1066 dp).

Это **один AVD с двумя конфигурациями окна**, не два независимых устройства и не
выполнение требования о трёх AVD. После проверки override сброшен к 1080 × 2400/420 dpi.
Приёмочная матрица API 30/35/36 остаётся отдельной задачей этапа 9.
Подключённый физический телефон не использовался и не изменялся.

Финальные XML, textproto и логи прогонов сохранены локально:

- `.local/test-reports/stage2-phone-final/debug`;
- `.local/test-reports/stage2-tablet-final/debug`.

Обычный HTML UI-отчёт: `android/app/build/reports/androidTests/connected/debug/index.html`.
Модульный HTML: `android/app/build/reports/tests/testDebugUnitTest/index.html`.
Эти каталоги пересоздаются при новом запуске и не включаются в Git.

Визуально проверены начальный экран телефона, русский календарь, результаты и карточка
гостиницы, начальный экран планшетного окна с двумя колонками. Снимки находятся
в `.local/screenshots/stage2`.
При визуальной проверке исправлены цвет выбранных элементов под фирменную палитру и
заголовок календаря: даты не переносятся неравномерно на узком экране.

Ранее найденная ошибка UI-теста была исправлена: для невидимого элемента ленивого списка
расчёта используется прокрутка контейнера к `quote_total`, а не обращение к ещё не созданному
элементу. Финальные серии после исправления прошли полностью.

## Ограничения, которые не скрываются интерфейсом

Дата и вместимость пока используются для проверки формы и предварительного подбора,
а **не для проверки свободных физических номеров**. Нет сетевой загрузки предметного
каталога, Room, входа, JWT, SQL-заказов, администратора, PDF-чеков и Google Maps.
Избранное — состояние UI, не постоянное хранилище или аккаунт. Изображения повторяются
в каталоге и являются созданными иллюстрациями: см. `ASSETS.md`.

Ни один REST API заказа или оплаты не вызывается. Услуги трансфера не заказывают машину;
точные реквизиты аэропорта и рейса будут обрабатываться при реализации этапа 5.
Код билетов, такси и проката автомобилей не добавлялся вне согласованной очередности.
GitHub-публикация и полноценная приёмка всего курсового проекта пока не выполнялись.

Следующий этап: предметные SQL-таблицы, миграции, каталог, регистрация/вход и серверная
проверка ролей USER/ADMIN. Только после этого локальный репозиторий заменяется REST-данными.

## Готовность запуска из Android Studio

Открыт проект `HotelCoursework/android`. Проверена существующая конфигурация `app`:
тип Android App, модуль `HotelCourseworkAndroid.app`, launch `default_activity`,
before-run `Android.Gradle.BeforeRunTask`, deploy APK включён, очистка хранилища выключена.
В панели IDE выбран `HotelCoursework API36`; кнопка Run доступна. Manifest содержит
экспортируемую launcher `MainActivity`. CLI-сборка, установка и запуск этой Activity проверены.

Для UI-прототипа достаточно Run: отдельный запуск backend для просмотра каталога не нужен.
Сервер нужен только для настоящей проверки соединения в профиле. Не следует запускать
`connectedDebugAndroidTest` вместо `app`: после тестов runner может удалить приложение.
